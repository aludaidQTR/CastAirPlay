## Phase 0 decision

**Phase 0 is not complete.** The MFT decoder spike passed, but no compatible
DirectShow filter has been validated, the phone USB spikes require physical
devices, and the Media Foundation virtual-camera spike requires Windows 11.
Do not begin Phase 1 until the DirectShow architecture is resolved. Continue
with throwaway Phase 0 probes; schedule the hardware-dependent checks for the
corresponding devices and OS.

## Reproducible environment probes

Read-only PowerShell probes queried `Win32_OperatingSystem`, located `adb`,
checked Apple Mobile Device Service, and ran `adb devices -l`. The decoder
spike source is in `spikes/mf_decoder/main.cpp`; its generated sample, NV12,
PNG, and executable are ignored under `build/spikes/`. Results are summarized
above. `MFCreateVirtualCamera`'s minimum supported
client version is documented by Microsoft at
<https://learn.microsoft.com/windows/win32/api/mfvirtualcamera/nf-mfvirtualcamera-mfcreatevirtualcamera>.

The decoder probe was built from a Visual Studio x64 developer environment
with:

```powershell
ffmpeg -f lavfi -i testsrc2=size=320x240:rate=1 -frames:v 1 -c:v libx264 -preset ultrafast -tune zerolatency -profile:v baseline -x264-params repeat-headers=1:annexb=1 -f h264 sample.h264 -y
cl /nologo /std:c++17 /EHsc /W4 /DUNICODE /D_UNICODE main.cpp /Fe:mf_decoder.exe /link mfplat.lib mfuuid.lib ole32.lib
mf_decoder.exe sample.h264 frame.nv12
ffmpeg -f rawvideo -pixel_format nv12 -video_size 320x240 -i frame.nv12 -frames:v 1 frame.png -y
```

The DirectShow candidate review used the public repositories
<https://github.com/jozeta/camtest> (MIT) and
<https://github.com/dapexi/DCVirtualCamera> (Apache-2.0). Neither was
registered or redistributed.
